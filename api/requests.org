** Team week (org-scoped)
GET /orgs/ORG_ID/teams/TEAM_ID/week?week=YYYY-MM-DD
# Returns: 200 OK with {week_start, rows: [{membership_id, user, plan_id,
# status, tasks_done, tasks_total, shipped}]}
# Note: one row per CURRENT team member, including members with no plan that
# week (status "not_started", plan_id null, 0/0, shipped null). `week` must be a
# Monday (422 otherwise); it defaults to the current week. Only plans filed
# under THIS team count — a member in two teams files one plan under one of
# them, so the other team reads as not_started.
# Errors: 403 forbidden (a teammate who is not the team lead),
# 404 not_found (no read access to the team),
# 422 validation_error (week is not a Monday)
# Requires: the lead of the team, an org admin, or an org owner

** Team history (org-scoped)
GET /orgs/ORG_ID/teams/TEAM_ID/history?limit=12&offset=0
# Returns: 200 OK with {items, total, limit, offset, shipped_rate}; items are
# {week_start, total, submitted_count, approved_count, done_count, shipped_count}
# Note: PAST weeks only (week_start before the current week), newest first.
# `total` counts every plan filed under the team that week (any status).
# `shipped_rate` = shipped plans / all plans over the RETURNED page (rounded to
# 4 dp; null when the page has no plans). `total` (pagination) is the number of
# past weeks with any plan.
# Errors: 403 forbidden (a teammate who is not the team lead),
# 404 not_found (no read access to the team)
# Requires: the lead of the team, an org admin, or an org owner

* AI (org-scoped, stateless)                                             :verb:
Template http://localhost:8000/app
# Access-Token: Bearer TOKEN

** Review a plan (org-scoped)
POST /orgs/ORG_ID/ai/plan-review
Content-Type: application/json
# Returns: 200 OK with PlanReview {verdict: "approve"|"adjust", summary,
# findings: [{task_ref, category, severity, problem, action, suggested_rewrite,
# suggested_kind}]}
# Note: STATELESS — reviews the caller's LIVE form state (no plan id, so no
# IDOR surface) and writes nothing to the database. The plan is sent to the
# model as untrusted data inside <plan>...</plan>. Every attempt (success or
# failure) records one ai_calls row in its own committed session; that row
# never contains plan, prompt or output text (metadata only).
# Errors: 404 not_found (not a member; cross-org id), 403 org_suspended,
# 422 validation_error (0 tasks -> NO model call, > 12 tasks, title > 200,
# why > 500, unknown fields), 429 ai_rate_limited (local per-user/per-org limit
# or upstream 429; Retry-After set), 502 ai_bad_output (invalid output after
# retries) / ai_error (any other failure), 503 ai_unavailable (no key),
# 504 ai_timeout
# Requires: a member of the org

{
  "week_start": "2026-10-12",
  "tasks": [
    {"ref": "t1", "kind": "main", "title": "Checkout handles expired cards", "why": "Users are blocked at payment"},
    {"ref": "t2", "kind": "gtm", "title": "Ship a changelog entry"}
  ]
}

** Draft a plan from notes (org-scoped)
POST /orgs/ORG_ID/ai/plan-draft
Content-Type: application/json
# Returns: 200 OK with PlanDraft {main, sub_goals[], gtm_goals[], left_out[],
# open_questions[]}
# Note: STATELESS — NEVER writes a plan or task; the result pre-fills the client
# form, which the user edits and saves. Notes are untrusted data inside
# <notes>...</notes>. Same ai_calls recording rules as plan-review.
# Errors: 404 not_found, 403 org_suspended, 422 validation_error (empty notes,
# notes > 4000, unknown fields), 429 ai_rate_limited, 502 ai_bad_output /
# ai_error, 503 ai_unavailable, 504 ai_timeout
# Requires: a member of the org

{
  "week_start": "2026-10-12",
  "notes": "Ship checkout by Friday, add an analytics event and update the changelog."
}
